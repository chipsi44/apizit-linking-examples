APIZIT Linking 0.5.0 planning draft

This page reserves the public release-note structure for a possible 0.5.0 line. It records compatibility decisions and publication gates without presenting future work as an available package.

Do not install or depend on 0.5.0 from this page. No 0.5.0 package or release candidate is claimed here. The current public package is 0.4.0 on PyPI.

Current reproducible command

Published version only
python -m pip install "apizit-linking[preview]==0.4.0"

Compatibility decisions for the draft

Contract 0.4 to proposed 0.5 treatment
User-authored manifest Manifest version: 1 remains unchanged.
Generated runtime artifact Runtime artifact version: 1 remains unchanged.
Artifact engine identity Exact engine_version matching remains mandatory, so artifacts must be recompiled with the released 0.5 engine.
HTTP responses Response changes in this public preparation are documentary only. They do not add a new declarative response-control contract.
Legacy route-list adapter The deprecated bridge is planned to remain through 0.5 under the public one-following-minor policy; earliest normal removal is 0.6.

Artifact format and engine compatibility answer different questions. Keeping artifact version: 1 means the envelope shape stays readable; it does not make a 0.4-generated artifact executable by a 0.5 runtime.

APIZIT integration gate

APIZIT must not pre-pin an unpublished version. After a 0.5 package is successfully published and verified on PyPI, APIZIT must change its exact dependency pin, recompile every Linking artifact, rebuild ZIP and container outputs, and record the released engine version plus artifact hash in deployment provenance. No private Linking source should be copied into APIZIT.

The complete documentary checklist is in the 0.4-to-0.5 migration guide .

Required publication gates

  • All engine, packaging, schema, adapter, and supported-Python tests pass.
  • Wheel and source distribution are built from the intended immutable commit.
  • PyPI Trusted Publishing succeeds and file hashes are recorded.
  • The installed distributions pass smoke tests in a clean environment.
  • APIZIT passes scan, report, ZIP, image, and runtime integration tests.
  • These notes are replaced with observed behavior, an actual publication status, and final migration evidence.

When this becomes an RC

A release candidate must have a real, uniquely versioned distribution and test evidence. At that point this page will name the candidate exactly, link to its canonical package files, list known blockers, and state whether it is appropriate only for testing. Until then, “0.5.0 / RC” is a planning label.
