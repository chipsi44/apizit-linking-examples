APIZIT Linking 0.5.0rc1

The first 0.5 candidate adds useful OpenAPI 3.1 documentation and minimal documentary responses while preserving the V1 manifest and runtime-artifact formats.

Publication status: 0.5.0rc1 is available from PyPI as a wheel and source distribution. It is intended for isolated evaluation. 0.4.0 remains the stable beta and final 0.5.0 is not published.

Evaluate the exact candidate

Disposable virtual environment
python -m pip install "apizit-linking[preview]==0.5.0rc1"
apizit-linking validate .
apizit-linking preview . --port 8080

Do not change this examples repository's requirements.txt, guide commands, CI pin, or a production integration from 0.4.0 merely to try the candidate.

Observed 0.5.0rc1 behavior

  • Local preview exposes Swagger UI, ReDoc, and an OpenAPI 3.1 document. If a linked GET or HEAD route would shadow a standard documentation path, preview relocates its documentation URLs.
  • OpenAPI operations are generated statically from the compiled contract. The generator does not import or execute customer modules to inspect metadata.
  • Explicit path, query, header, JSON body, form, and file bindings are described with source-aware wire schemas. Defaults, nullable annotations, repeated values, and automatic source resolution are represented.
  • Operations document a minimal successful 200, stable Linking request errors as 400, and generic business failures as 500. HEAD does not advertise a response body.
  • Linking remains responsible for request resolution, so this change does not introduce FastAPI/Pydantic request 422 responses.

Compatibility decisions

Contract 0.4 to 0.5.0rc1 treatment
User-authored manifest Manifest version: 1 remains unchanged.
Generated runtime artifact Runtime artifact version: 1 remains unchanged.
Artifact engine identity Exact engine_version matching remains mandatory, so artifacts must be recompiled with the candidate engine.
HTTP responses Response schemas are documentary only. Return annotations do not validate or transform customer return values, and there is no new manifest response block.
Legacy route-list adapter The deprecated bridge remains through 0.5 under the public one-following-minor policy; earliest normal removal is 0.6.

Artifact format and engine compatibility answer different questions. Keeping artifact version: 1 means the envelope shape stays readable; it does not make a 0.4-generated artifact executable by the candidate runtime.

Responses are documentary only

The OpenAPI return schema is a useful description derived from the Python annotation, not a runtime response contract. APIZIT Linking sets no FastAPI response model and does not reject, coerce, or reshape a returned value to match that annotation. FastAPI still performs its normal response serialization. Custom status codes, response headers, streaming, and user-configured response models remain outside manifest v1.

APIZIT is not yet promoted

Publication of the candidate does not promote APIZIT automatically. APIZIT remains on its current stable integration until its separate candidate validation updates the exact dependency pin, recompiles every Linking artifact, rebuilds ZIP and container outputs, verifies deployment provenance, and proves that no Linking engine source is vendored.

The complete documentary checklist is in the 0.4-to-0.5 migration guide .

Completed publication gates

The release workflow completed nine gated jobs before PyPI publication:

  • one immutable wheel and source-distribution build;
  • six clean-environment smoke jobs installing the exact same wheel on Linux, Windows, and macOS with Python 3.10 and 3.14;
  • one smoke with the minimum supported preview dependencies on Python 3.10;
  • one PyPI Trusted Publishing job.

Each wheel smoke verified the installed CLI, public schema, OpenAPI document, FastAPI adapter, and a real ASGI request outside the source checkout. These package gates passed; the separate APIZIT promotion gate remains pending.

Before final 0.5.0

Evaluate 0.5.0rc1 against real projects and the separate APIZIT integration. Report security findings privately and non-security defects through the public examples repository. A final 0.5.0 release will require its own exact package, completed gates, migration evidence, and explicit publication; this page does not claim that final release exists.
