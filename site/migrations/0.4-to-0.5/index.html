Published candidate · isolated evaluation

Evaluate 0.4 to 0.5 with 0.5.0rc1

The 0.5 candidate keeps the two public V1 formats stable while retaining exact engine identity. The files look familiar, but every runtime artifact still has to be regenerated with the candidate for an isolated evaluation.

This is candidate evaluation guidance, not a production upgrade. Package 0.5.0rc1 is published, but final 0.5.0 is not published. Keep production, stable test fixtures, examples, and guides pinned to apizit-linking==0.4.0.

Create a separate evaluation environment

Exact RC pin
python -m venv .venv-050rc1
# Activate .venv-050rc1, then:
python -m pip install "apizit-linking[preview]==0.5.0rc1"
apizit-linking validate .
apizit-linking preview . --port 8080

The package files are canonical on the PyPI 0.5.0rc1 page . Use an exact pin and keep the stable 0.4.0 environment available for comparison and rollback.

What remains unchanged

  • User-authored Linking manifests continue to declare version: 1.
  • The closed runtime-artifact envelope continues to declare version: 1.
  • The artifact remains a generated, opaque build output rather than a file users or adapters edit.
  • create_app_from_runtime_artifact remains the supported FastAPI adapter entry point.
  • The legacy create_app_from_runtime_routes bridge remains for this following minor under the 0.x deprecation policy.

Why recompilation is mandatory

The artifact envelope carries an exact engine_version. The 0.5.0rc1 runtime must reject an artifact compiled by 0.4.0 even though both artifacts declare runtime artifact version: 1. Format version 1 says the envelope has the same contract; exact engine identity says which implementation verified and serialized the callable metadata.

Re-run the compiler with the exact candidate engine. Never replace engine_version in JSON, copy routes between artifacts, or suppress the mismatch check.

Response scope is documentary only

Version 0.5.0rc1 documents a minimal 200, stable Linking 400, and generic 500 in OpenAPI. These descriptions do not introduce declarative status codes, custom response headers, response models, or streaming behavior. Return annotations are not used to validate, transform, reject, or reshape customer return values at runtime.

Project-owner RC checklist

  1. Read the 0.5.0rc1 release notes and confirm the exact candidate version.
  2. Install 0.5.0rc1 from PyPI in a clean, non-production environment.
  3. Run apizit-linking validate against the unchanged manifest v1.
  4. Compile a new artifact with 0.5.0rc1; keep artifact version 1.
  5. Inspect /openapi.json, Swagger UI, and ReDoc in preview.
  6. Run startup, success, conversion-error, and business-error tests.
  7. Discard candidate outputs after evaluation; do not replace stable production outputs.

APIZIT evaluation must re-pin and rebuild

APIZIT currently consumes Linking as a separate released framework and has not yet been promoted to 0.5.0rc1. A candidate-only integration branch may evaluate the RC, but it must:

  1. change its exact build and runtime pin from 0.4.0 to 0.5.0rc1;
  2. compile each discovered manifest again with that exact package;
  3. record the source revision, engine version, manifest version, and artifact hash;
  4. rebuild Lambda ZIPs and container images without vendored Linking code;
  5. run scan, report, ZIP, image, startup, and end-to-end request tests;
  6. prove that documentation remains non-enforcing when return values differ;
  7. keep stable APIZIT promotion blocked until the final release decision.

Rollback must also recompile

If APIZIT rolls back to 0.4.0, it must restore the exact 0.4.0 dependency and deploy an artifact freshly compiled by 0.4.0, or a preserved immutable 0.4.0 output with proven provenance. A new artifact cannot be made compatible by editing its engine field.

Follow the canonical release signal

Follow the published 0.5.0rc1 release notes for observed behavior and completed package gates. PyPI is the canonical source of the candidate files. A final 0.5.0 requires a separate publication and is not implied by this RC.
